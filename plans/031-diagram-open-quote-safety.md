## At a glance

- **What**: Make `diagram-open` reject dangerous URL characters, pass the URL via the environment instead of string interpolation, validate `ARTIFACTS_SITE_URL`, and stop probing arbitrary local ports, applied identically to all three copies.
- **Why**: The opener interpolates a filename-derived URL into a single-quoted PowerShell literal, so a single quote in an agent-generated filename is command injection on the Windows host.

## Why this matters

`diagram-open` opens an artifact page in the user's browser after a skill
writes it. On WSL2 (this repo's primary environment) the opener shells out to
`powershell.exe -NoProfile -Command "Start-Process '$url'"`, interpolating
`$url` inside a **single-quoted PowerShell literal**. Artifact filenames are
generated by agents from prompt and ingested-source content, so a single quote
reaching a filename closes the literal and the remainder of the path is parsed
as PowerShell — command injection on the Windows host from opening a diagram.
Two lesser issues share the file: `ARTIFACTS_SITE_URL` is taken unvalidated as
the first base URL to open, and every locally-listening TCP port is probed with
a GET of the artifact path (disclosing the path to unrelated local services and
letting whichever answers first choose the opened origin). After this plan the
opener rejects dangerous URL characters up front, passes the URL to PowerShell
via the environment instead of string interpolation, validates
`ARTIFACTS_SITE_URL`, and stops probing arbitrary ports.

There are **three byte-identical copies** of this script (one per plugin), and
they must stay identical — plan 034 adds a hash-equality check that fails if
they diverge. Apply every change to all three.

The opener block (lines 65–76) — line 68 is the injection point:

```bash
if command -v wslview >/dev/null 2>&1; then
  wslview "$url"
elif grep -qi microsoft /proc/version 2>/dev/null; then
  powershell.exe -NoProfile -Command "Start-Process '$url'" >/dev/null 2>&1 || cmd.exe /c start "" "$url" >/dev/null 2>&1
elif command -v xdg-open >/dev/null 2>&1; then
  xdg-open "$url" >/dev/null 2>&1 &
elif command -v open >/dev/null 2>&1; then

else

fi
```

The script is `set -euo pipefail` (line 8). `$url` can be either a local
Windows path (after `wslpath -w`, containing backslashes and a drive letter) or
an `http://127.0.0.1:PORT/...` URL — so any allow-list must permit both shapes.

## Steps

Make the **same** edits in all three files. The simplest safe workflow: edit
`plugins/diagrams/bin/diagram-open` fully, then copy it over the other two
(`cp plugins/diagrams/bin/diagram-open plugins/plans/bin/diagram-open` and
likewise for `decisions`) so they stay byte-identical. Preserve the executable
bit (`cp` over an existing executable keeps it; verify in Done criteria).

### Step 1: Reject dangerous URL characters up front

Immediately after `url="${1:?usage: diagram-open <url-or-file>}"` (line 9), add
a guard that rejects control characters, quotes, and shell/PowerShell
metacharacters before any opener or path logic runs. Allow the characters that
legitimately appear in a local Windows path or a localhost URL (letters,
digits, and ``/ \ : . _ - ~ % # ? = & @ + space``):

```bash
case "$url" in
  *[\'\"\`\$\;\|\&\<\>$'\n'$'\r']*)
    echo "diagram-open: refusing URL with unsafe characters: $url" >&2
    exit 1
    ;;
esac
```

Note `&` is included in the reject set above; if a legitimate artifact URL ever
needs `&` (query strings), relax it then — current artifact paths do not use
query strings. Keep the guard conservative.

**Verify**: `bash -n plugins/diagrams/bin/diagram-open` → exit 0.

### Step 2: Pass the URL to PowerShell via the environment, not string interpolation

Replace line 68 so PowerShell reads the URL from an environment variable it
expands itself (`$env:URL`), never from a bash-interpolated literal:

```bash
elif grep -qi microsoft /proc/version 2>/dev/null; then
  URL="$url" powershell.exe -NoProfile -Command 'Start-Process $env:URL' >/dev/null 2>&1 || cmd.exe /c start "" "$url" >/dev/null 2>&1
```

The `cmd.exe` fallback keeps `"$url"` as a normal double-quoted bash argument
(cmd's `start` takes it as an argument, not a script), which Step 1's guard has
already made safe.

**Verify**: `bash -n plugins/diagrams/bin/diagram-open` → exit 0.

### Step 3: Validate `ARTIFACTS_SITE_URL` and drop the all-ports probe

In the candidates block (lines 38–52), (a) only accept `ARTIFACTS_SITE_URL` when
it is a loopback http(s) URL, and (b) remove the `ss`-driven all-ports probe,
leaving the two explicit default candidates:

```bash
    candidates=()
    if [ -n "${ARTIFACTS_SITE_URL:-}" ]; then
      case "${ARTIFACTS_SITE_URL%/}" in
        http://127.0.0.1|http://127.0.0.1:[0-9]*|http://localhost|http://localhost:[0-9]*|https://127.0.0.1|https://127.0.0.1:[0-9]*|https://localhost|https://localhost:[0-9]*)
          candidates+=("${ARTIFACTS_SITE_URL%/}") ;;
        *)
          echo "diagram-open: ignoring non-loopback ARTIFACTS_SITE_URL" >&2 ;;
      esac
    fi
    candidates+=("http://127.0.0.1:3000" "http://localhost:3000")
    for base in "${candidates[@]}"; do
      if http_ok "$base/artifacts/view/$rel"; then
        url="$base/artifacts/review/$rel"
        break
      fi
    done
```

This removes the `if command -v ss …` block entirely. The default port 3000
matches `site/package.json`'s dev/start (`-H 127.0.0.1`); if the site runs on a
non-default port, the operator sets `ARTIFACTS_SITE_URL` (now validated).

**Verify**: `bash -n plugins/diagrams/bin/diagram-open` → exit 0.
