## Deviations from the planned order

`001` ran as written. `003`, `004` and `005` were folded in together out of a
UI prototype (branch `prototype/diagram-page-variants`) rather than executed as
three sequential plans, because the prototype answered what all three were
guessing at: what the page should actually look like. Two consequences:

- **002 never ran, so none of this is verified by a render harness.** The
  geometry was checked against stubbed viewports, and the page was opened by
  hand. Nothing measured a real rendered diagram. 002 is now the next plan, and
  its allowances should be set against the current template, not the old one.
- **004 is partial.** Geist tokens now drive the diagram, but the fonts still
  come from Google Fonts rather than being inlined. Inlining was not needed to
  answer the prototype's question and was left alone.

`006` and `007` are unchanged and still depend on this work.

## Dependency notes

- **001 is first because nothing else reaches the user without it.** The
  installed plugin is pinned to `gitCommitSha: cc5b0de` — the first of three
  commits — because the version has been `0.1.0` throughout. Everything since is
  cached out of existence.
- **002 before 003–007**: those four plans all change how a diagram renders, and
  none of them is falsifiable without a harness that opens a real page and
  measures it. 002 builds that harness; 003 and 004 clear the allowances it has
  to start with.
- **003 → 004 → 005 are strictly sequential** — all three edit
  `skills/diagram-plans/MERMAID.md`. They own disjoint regions so the diffs do
  not collide, and each plan states which region it owns:
  - 003: layout CSS, error markup, `<script>` structure, pan/zoom
  - 004: `:root` tokens, inlined fonts, the body of `themeConfig(dark)`
  - 005: the `theme`/`look`/`layout` keys, the ELK import, the type table
    Running them out of order, or letting one stray into another's region, will
    produce conflicts that are tedious rather than interesting.
- **006 before 007**: 006 writes the budget into `SKILL.md`; 007's
  `diagram-check` enforces it. Enforcing a budget that has not been stated
  produces failures the model cannot act on.
- **008 is independent** of everything else and can run in parallel from the
  start. Its version bump is the only coupling — read the current version rather
  than assuming one.

**Deliberately deferred**, with reasons in `000-research-diagram-engines.md`:

- **Graphviz-WASM as a second engine.** Verified viable (821 KB, no Web Worker,
  works from `file://`, `splines=ortho` gives true right angles), but building a
  second engine before knowing Mermaid+ELK is insufficient is speculative.
  Revisit after a few weeks of real use.
- **Authored inline SVG** in the `diagram-design` style. Highest ceiling, but
  expensive per diagram and only honest with a geometry verifier. Same reasoning.
- **D2.** Rejected outright, not deferred: it needs a real Web Worker and ships
  22 MB of wasm, so it cannot run from a `file://` page at all.
- **Rendered-geometry checks** (overlapping nodes, edge crossings) — needs a
  real renderer; belongs with `DIAGRAM_PLANS_RENDER_CHECK`, not the default path.

## Findings considered and rejected

So nobody re-audits these:

- **`flowchart: { curve: "basis" }` is a bug** — it is not. `basis` is Mermaid's
  own schema default, so the setting is a no-op. Plan 003 changes it to
  `linear` as a readability preference, not a fix.
- **`themeVariables` are ignored on non-`base` themes** — false. Mermaid's
  `calculate()` applies user overrides both before and after deriving colours,
  so they stick on any theme. Plan 004 uses `theme: "base"` because it derives a
  coherent palette from fewer variables, not because the others ignore overrides.
- **The hook's greedy `.*"prompt"` regex matches the wrong key** — not
  reproducible. Nested JSON arrives backslash-escaped (`\"prompt\"`), which the
  pattern's literal quotes do not match. Plan 008 still rewrites the parse, for
  the SIGPIPE fix and readability — not for this.
- **The hook crashes on prompts over 4,000 bytes** — the threshold is the 64 KB
  pipe buffer, not 4,000 bytes. Reproduced at ~300 KB (exit 141); a 6 KB prompt
  is fine. Plan 008 has the corrected reproduction.
- **`${CLAUDE_PLUGIN_ROOT}` is unset so `SKILL.md` step 4 is broken** — half
  right. It is genuinely unset in the Bash tool's environment, but the plugins
  reference documents that it is _substituted inline_ in skill content, so the
  skill's usage is legitimate. The real breakage was that the installed copy has
  no `scripts/` directory at all (finding 1). Plan 001 moves to `bin/` for
  robustness, not to fix a substitution bug.
- **Adopting Vercel's `vercel-brand.css` directly** — rejected. It is Vercel's
  _brand report_ foundation and carries a wordmark header and triangle footer as
  part of its contract; using it would brand a user's private planning diagrams
  as Vercel documents. Plan 004 takes the token values, not the identity.
