# Research: dotfiles tool for two Macs with per-machine differences and exclusions

Ticket: [../issues/01-dotfiles-tool.md](../issues/01-dotfiles-tool.md)
Date: 2026-08-25
Builds on: `wiki/dotfiles-management.md` (bare repo, Stow, chezmoi at a high level). This note only adds what that page lacks: per-machine conditionals, exclusion, secrets, and the repo-to-`$HOME` edit flow.

## Recommendation (short)

**chezmoi**, with the monorepo as the git working tree and a `dotfiles/` subdirectory as the chezmoi source state. Reasons, each backed below:

1. It is the only candidate with first-class per-machine conditionals (`.chezmoi.hostname`, prompted per-machine data) **and** a per-machine ignore file that is itself a template.
2. Secrets never enter git: password-manager template functions (1Password, macOS Keychain, etc.) or `encrypted_` files.
3. The web-UI requirement ("edit a file in the repo, change lands in `$HOME`") maps to one command, `chezmoi apply --source-path <file>`; there is a `--watch` mode but it is tied to `chezmoi edit`, so the UI should call `apply` itself.

Hard constraint no tool solves: **"exclude some repo content entirely from the work machine" cannot be done with one git repo.** Every dotfiles tool, and `git sparse-checkout`, still clones the full history to the work machine. True exclusion needs the excluded content in a separate private repo (pulled in only on the personal machine) or encrypted at rest. See "Exclusion" below.

## Per-machine conditionals

| Tool             | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                       | Source                                                                                                                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| chezmoi          | Go templates in any `*.tmpl` file. Built-ins include `.chezmoi.hostname` (name up to first dot), `.chezmoi.os`, `.chezmoi.username`, `.chezmoi.homeDir`. Per-machine data lives in `~/.config/chezmoi/chezmoi.toml` `[data]`, and `chezmoi init` can generate that file from `.chezmoi.toml.tmpl` in the repo using `promptStringOnce` (asks once, e.g. "email"). Example in docs: `dot_gitconfig.tmpl` with `email = {{ .email | quote }}`; and `{{- if eq .chezmoi.hostname "work-laptop" }} ... {{- end }}`.                                                                                                                                                                            | [template variables](https://www.chezmoi.io/reference/templates/variables/), [machine-to-machine differences](https://www.chezmoi.io/user-guide/manage-machine-to-machine-differences/), [setup](https://www.chezmoi.io/user-guide/setup/) |
| GNU Stow         | None. Manual documents only symlink creation, `--ignore`, folding. Per-machine variation = separate packages stowed per machine by a script you write, or per-tool `include` directives (git's `[include]`, zsh sourcing a local file).                                                                                                                                                                                         | [Stow manual](https://www.gnu.org/software/stow/manual/stow.html)                                                                                                                                                                                        |
| Nix home-manager | Full Nix language; per-host = separate `homeConfigurations` or module conditionals. Powerful but requires Nix on both Macs and the nix-darwin module for system integration.                                                                                                                                                                                                                                                    | [nix-darwin module](https://raw.githubusercontent.com/nix-community/home-manager/master/docs/manual/installation/nix-darwin.md), [configuration](https://raw.githubusercontent.com/nix-community/home-manager/master/docs/manual/usage/configuration.md) |
| Bare git repo    | None. Branch-per-machine is the common workaround (not covered by primary docs; wiki page covers the technique).                                                                                                                                                                                                                                                                                                                | `wiki/dotfiles-bare-git-repo.md`                                                                                                                                                                                                                         |

Work git identity and proxies fit chezmoi's model exactly: templated `dot_gitconfig.tmpl`, a `[data] work = true` value set once via `promptBoolOnce`, and `{{ if .work }}` blocks.

## Ignore / exclude

- **chezmoi `.chezmoiignore`**: "interpreted as a template, whether or not it has a `.tmpl` extension." Patterns match the _target_ path with doublestar globs; `!` negates; subdirectory `.chezmoiignore` files scope to that subdirectory. Docs' own example: `{{- if ne .chezmoi.hostname "work-laptop" }} .work {{- end }}` — i.e. "ignore X unless on host Y". Default posture: "chezmoi ignores everything that you haven't explicitly added." ([chezmoiignore](https://www.chezmoi.io/reference/special-files/chezmoiignore/), [FAQ usage](https://www.chezmoi.io/user-guide/frequently-asked-questions/usage/))
- **Stow**: `--ignore <perl regex>`, `.stow-local-ignore` (per package), `~/.stow-global-ignore`, built-in defaults (`.git`, `README.*`, `LICENSE.*`, editor backups). Not conditional. Beware tree folding: Stow may make `~/.config` itself a symlink into the stow dir; use `--no-folding`. `--dotfiles` maps `dot-foo` to `.foo`. ([Stow manual](https://www.gnu.org/software/stow/manual/stow.html))
- **home-manager**: exclusion is just "don't declare the file" in that host's config.
- **git sparse-checkout**: only changes the working tree ("change the working tree from having all tracked files present to only having a subset"); objects stay in `.git`. Command is marked EXPERIMENTAL in its own man page; non-cone mode deprecated. Partial clone (`--filter=blob:none`) defers blob download but "allows objects to be faulted in" on demand and "requires that the user be online" — it is a performance feature, not access control. ([git-sparse-checkout](https://git-scm.com/docs/git-sparse-checkout), [git-clone](https://git-scm.com/docs/git-clone), [partial-clone](https://git-scm.com/docs/partial-clone))

**Conclusion on exclusion.** `.chezmoiignore` keeps files out of the work `$HOME`, but the work clone still holds them. If "exclude entirely" means "must not exist on the work disk", options are:

1. Second private repo for personal-only content, pulled by chezmoi only on the personal machine via `.chezmoiexternal` (`type: git-repo`; the file "is interpreted as a template", so wrap the entry in a hostname condition). ([chezmoiexternal](https://www.chezmoi.io/reference/special-files/chezmoiexternal-format/))
2. Encrypt the personal-only files (`encrypted_` prefix, age/gpg; `chezmoi add --encrypt`) and never place the key on the work machine. Ciphertext is still present on disk. ([encryption](https://www.chezmoi.io/user-guide/encryption/))
3. Git submodule pointing at the private repo, not initialised on work. (Standard git; not researched further.)
   Which one applies depends on the wiki content question: does the _wiki_ (not just dotfiles) also need partial exclusion on work? That is a new map question.

## Secrets

- **chezmoi**: template functions for 1Password, Bitwarden, KeePassXC, pass, gopass, Vault, AWS Secrets Manager, Azure Key Vault, macOS **Keychain**, and others; "When chezmoi applies a template with a secret referenced from a password manager, it will automatically fetch the secret value and insert it into the generated destination file." Example: `export CF_API_TOKEN='{{ onepasswordRead "op://Personal/cloudlfare-api-token/password" }}'`. Plus `encrypted_` files (age, gpg, rage) — `chezmoi edit` decrypts/re-encrypts transparently. Private files get `private_` prefix (clears group/world bits, which git cannot store). ([password managers](https://www.chezmoi.io/user-guide/password-managers/), [encryption](https://www.chezmoi.io/user-guide/encryption/), [target types](https://www.chezmoi.io/reference/target-types/))
- **Stow / bare repo**: nothing built in; discipline plus tool-level includes (e.g. `~/.gitconfig.local` untracked).
- **home-manager**: the manual has no secrets chapter (checked `usage/` pages; none found). Community modules (sops-nix, agenix) exist but were not verified against primary docs — **unverified**.

## How edits reach `$HOME`

| Tool         | Model                                                                                                                                                                                                 | Repo edit shows up in `$HOME`...                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| chezmoi      | Generates real files at apply time.                                                                                                                                                                   | After `chezmoi apply` (or `chezmoi apply --source-path <edited file>`, "useful for applying changes after editing"). `chezmoi edit --apply` applies on editor exit; `chezmoi edit --watch` applies on each save but "only functions when `chezmoi edit` receives file arguments", watches only the edited files (not `.chezmoitemplates`), and needs `edit.hardlink` working. Reverse direction: `chezmoi re-add` pulls `$HOME` edits back into source but "will not overwrite templates". Config: `git.autoCommit` / `git.autoPush` (default false) commit and push on every source change. ([apply](https://www.chezmoi.io/reference/commands/apply/), [edit](https://www.chezmoi.io/reference/commands/edit/), [re-add](https://www.chezmoi.io/reference/commands/re-add/), [config vars](https://www.chezmoi.io/reference/configuration-file/variables/), [daily ops](https://www.chezmoi.io/user-guide/daily-operations/)) |
| Stow         | Symlinks.                                                                                                                                                                                             | Immediately; no apply step. Only `--restow` needed when files are added/removed. Cannot template, encrypt, or set permissions (symlink cannot diverge from source).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| home-manager | Symlinks into the read-only Nix store, via a `home-files` generation, then `ln -sfn` into `$HOME`; collision check aborts unless `-b backup` or `force = true` ("can silently delete local changes"). | After `home-manager switch` (a full Nix evaluation/build). `mkOutOfStoreSymlink` lets a file point at a mutable path outside the store, giving Stow-like immediacy for chosen files. Rollback: `home-manager switch --rollback`. ([dotfiles](https://raw.githubusercontent.com/nix-community/home-manager/master/docs/manual/usage/dotfiles.md), [files.nix](https://raw.githubusercontent.com/nix-community/home-manager/master/modules/files.nix), [rollbacks](https://raw.githubusercontent.com/nix-community/home-manager/master/docs/manual/usage/rollbacks.md))                                                                                                                                                                                                                                                                                                                                                           |
| Bare repo    | Files tracked in place.                                                                                                                                                                               | Immediately; the repo _is_ `$HOME`. No templating; pre-existing files block checkout on a new machine.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Implication for the web UI: with chezmoi the "save" handler is `write file` then `chezmoi apply --source-path <path>` (or `chezmoi apply` for a full sync). Do not rely on `--watch`.

## Monorepo fit

- chezmoi's `sourceDir` and `workingTree` are separate config values: `workingTree` is the "git working tree directory", default "source directory". Setting `sourceDir = ~/second-brain/dotfiles` and `workingTree = ~/second-brain` lets the wiki and dotfiles share one repo. `.chezmoiroot` is the alternative when the repo root is the source dir ("read the source state from a subdirectory of the source directory"). ([config vars](https://www.chezmoi.io/reference/configuration-file/variables/), [customize source dir](https://www.chezmoi.io/user-guide/advanced/customize-your-source-directory/))
- Stow works from any directory (`-d`, `-t`).
- home-manager: config can live anywhere via flake; heaviest install footprint (Nix daemon on both Macs).

## Tradeoffs summary

|                                  | chezmoi                                                           | Stow              | home-manager      | bare repo / sparse-checkout    |
| -------------------------------- | ----------------------------------------------------------------- | ----------------- | ----------------- | ------------------------------ |
| Per-machine conditionals         | built in                                                          | none              | full language     | branches only                  |
| Conditional exclude from `$HOME` | `.chezmoiignore` template                                         | no                | yes (declarative) | sparse-checkout (experimental) |
| Exclude from work _disk_         | no (needs 2nd repo / encryption)                                  | no                | no                | no                             |
| Secrets                          | pw managers, Keychain, age/gpg                                    | none              | none in manual    | none                           |
| Edit-to-`$HOME` latency          | apply step (one command)                                          | instant (symlink) | `switch` (slow)   | instant                        |
| Learning / install cost          | one Go binary; template syntax                                    | trivial           | Nix + nix-darwin  | trivial                        |
| Filename oddities in repo        | `dot_`, `private_`, `.tmpl` prefixes (deliberate; see design FAQ) | `dot-` optional   | n/a               | none                           |

Cost of chezmoi worth flagging: repo filenames are `dot_zshrc.tmpl` not `.zshrc`, so the web UI must map source names to target names (`chezmoi managed` / `chezmoi source-path` give the mapping).
