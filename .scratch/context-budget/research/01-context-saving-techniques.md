# Research: context-saving techniques for Claude Code / LLM coding-agent workflows

Type: research
Status: resolved
Date: 2026-08-27

Builds on: `wiki/open-source-local-context-reducers.md` (third-party reducers — this note covers only first-party Anthropic mechanisms), `wiki/context-reducer-design.md` (four reduction layers), `wiki/caveman-local-install.md`, and `plans/024-context-token-budget-guardrails.md` (baseline: ~13.7 KB ≈ 3.4k tokens injected per session). All claims below cite Anthropic primary sources fetched 2026-08-27. No prompt-injection content was encountered in any fetched page.

## Question

Which officially documented techniques keep context injection and token cost low in Claude Code / Claude API agent workflows, what does each save, and what does each cost?

## Findings

### 1. Prompt caching — changes the economics of stable injected context

- Multipliers ([pricing](https://platform.claude.com/docs/en/about-claude/pricing#prompt-caching)): 5-minute cache write 1.25x base input, 1-hour write 2x, cache read 0.1x. Reads refresh the TTL at no extra cost. Break-even: one read (5m TTL) or two reads (1h TTL).
- Mechanics ([prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)): prefix match over `tools` → `system` → `messages`; any byte change invalidates everything after it. Max 4 breakpoints; automatic top-level caching moves a breakpoint to the last cacheable block; 20-block lookback. Minimum cacheable prefix is model-dependent — 512 tokens (Opus 5/Fable 5), 1,024 (Opus 4.8, Sonnet 5/4.6/4.5), 2,048 (Opus 4.7), 4,096 (Opus 4.6/4.5, Haiku 4.5); shorter prefixes silently don't cache.
- Claude Code manages this automatically ([how Claude Code uses prompt caching](https://code.claude.com/docs/en/prompt-caching)). Key facts:
  - TTL is one hour on a subscription within included usage, five minutes on an API key / usage credits ([costs](https://code.claude.com/docs/en/costs#understand-costs)); a break longer than the TTL makes the next turn reprocess the full context uncached.
  - Cache invalidators: model switch (incl. each `opusplan` plan-mode toggle), any change to the tool-definition set (MCP server connect/disconnect when tools are loaded upfront; deny-rule on a built-in tool), effort/system-prompt changes. Mid-session CLAUDE.md edits neither invalidate nor apply — content reloads only on `/clear`, `/compact`, or restart. Skill invocations and plugin content append after the conversation and never invalidate the cache.
  - `/compact` while the cache is warm reads the prefix at 0.1x, so it "costs a fraction of what the context size suggests"; after a long break it reprocesses everything. `/clear` costs nothing.
- Implication for stable injected context (CLAUDE.md, skill descriptions): it is paid once per session as a cache write (1.25–2x) and then re-read at 0.1x every turn — cheap per turn but never free, and repaid in full by every cache miss and every fresh session.

### 2. Claude Code context mechanics — what is injected and when

- Session-start injection, per the official [context-window simulation](https://code.claude.com/docs/en/context-window): system prompt (illustrated at ~4,200 tokens), auto memory (first 200 lines or 25 KB), environment info, MCP tool *names* (schemas deferred), one-line skill descriptions, user `~/.claude/CLAUDE.md`, project CLAUDE.md. `/context` shows the live breakdown per category ([debug your configuration](https://code.claude.com/docs/en/debug-your-config)).
- CLAUDE.md ([memory](https://code.claude.com/docs/en/memory)): loaded every session; official guidance is **under 200 lines**; `@path` imports load at launch too (organization, not savings); nested CLAUDE.md files and `.claude/rules/*.md` with `paths:` frontmatter lazy-load only when Claude reads matching files — the documented way to make instructions pay-per-use. Docs recommend a CLAUDE.md that contains `@AGENTS.md` (import) rather than a duplicate file, to avoid divergence.
- Hooks ([hooks reference](https://code.claude.com/docs/en/hooks)): only `UserPromptSubmit`, `UserPromptExpansion`, and `SessionStart` stdout is added as context Claude sees; other events' stdout goes to the debug log. Hook output strings are capped at 10,000 characters. So a chatty prompt hook is a real per-prompt tax — plan 024's quiet-path probe targets exactly the documented injection channel.
- Compaction: auto-compaction summarizes when the conversation reaches the model's window (configurable 100K–1M via `/autocompact`, [model config](https://code.claude.com/docs/en/model-config#set-the-auto-compact-window)); `/compact <instructions>` and a `# Compact instructions` CLAUDE.md section steer what survives ([costs](https://code.claude.com/docs/en/costs#reduce-token-usage)). After `/compact`, the skill-description listing is *not* re-injected — only invoked skills are preserved, capped at 5,000 tokens each ([context window](https://code.claude.com/docs/en/context-window)).
- Subagents ([sub-agents](https://code.claude.com/docs/en/sub-agents)): each runs in its own context window and returns only a summary — the documented isolation lever for verbose work ("keeps exploration results out of your main conversation context"), with per-subagent `model:` (e.g. `haiku`) and `effort:` overrides to "control costs by routing tasks to faster, cheaper models". Caveat: every subagent re-pays the session-start injection (CLAUDE.md, skills — plan 024 already notes this). Agent teams cost ~7x a standard session ([costs](https://code.claude.com/docs/en/costs#plan-for-agent-team-usage)).
- Other documented cost levers on the [costs page](https://code.claude.com/docs/en/costs#reduce-token-usage): `/clear` between unrelated tasks; prefer CLI tools (`gh`, `aws`) over MCP servers; PreToolUse hooks that pre-filter output (grep a 10,000-line log down to matching lines "reducing context from tens of thousands of tokens to hundreds"); move workflow instructions out of CLAUDE.md into on-demand skills; lower effort / thinking for simple tasks; `/usage` flags behaviors ≥10% of recent usage.

### 3. Claude API context-management features

- **Context editing** (beta `context-management-2025-06-27`, [context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing)): server-side clearing of old tool results (`clear_tool_uses_20250919`, optionally tool inputs too) and thinking blocks (`clear_thinking_20251015`), with configurable `trigger` / `keep` / `clear_at_least` thresholds. Cost: clearing invalidates the cache at the cleared point — the doc explicitly says to clear enough tokens to make the invalidation worthwhile.
- **Server-side compaction** (beta `compact-2026-01-12`): the doc names it "the primary strategy for managing context in long-running conversations"; summarizes earlier context automatically (Claude 4.6+ models).
- **Memory tool** (`memory_20250818`, no beta on current SDKs, [memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)): client-side file store under `/memories` that persists across conversations — "keeps the active context focused on the current task"; the docs frame it as just-in-time retrieval per the [context-engineering post](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).
- **Token counting** ([token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting)): `POST /v1/messages/count_tokens` is **free**, with rate limits separate from message creation; counts are estimates. This is the ground truth for plan 024's byte→token conversions (better than the ~4 B/token heuristic).
- **1M context**: Claude 4.6+ models (and Sonnet 5, Opus 5, Fable 5) have a 1M window **by default, no beta header, at standard pricing** — "a 900k-token request is billed at the same per-token rate as a 9k-token request" ([context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows), [long context pricing](https://platform.claude.com/docs/en/about-claude/pricing#long-context-pricing)). Haiku 4.5 stays at 200K. A big window removes the *failure* mode, not the *cost*: full history is still billed every turn, which is why the costs page pushes `/clear` regardless.

### 4. Skills architecture — progressive disclosure

- The [Agent Skills engineering post](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills): "At startup, the agent pre-loads the name and description of every installed skill into its system prompt. This metadata is the first level of progressive disclosure… just enough information for Claude to know when each skill should be used without loading all of it into context." The body loads only on invoke.
- Claude Code specifics ([skills](https://code.claude.com/docs/en/skills)): combined `description` + `when_to_use` text is truncated at 1,536 characters per skill in the listing "to reduce context usage"; once a skill loads, its body "stays in context across turns, so every line is a recurring token cost"; `disable-model-invocation: true` (or `"user-invocable-only"` via the `skillOverrides` setting, **without editing the file**) keeps a skill entirely out of the startup listing — zero context until invoked with `/name`. `context: fork` runs a skill in its own subagent context.

### 5. MCP — tool-schema cost and deferred loading

- API-level [tool search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) (`tool_search_tool_regex_20251119` / `bm25`): mark tools `defer_loading: true`; a typical five-server setup consumes ~55k tokens of definitions up front, and tool search "typically reduces this by over 85 percent". Selection accuracy also degrades past 30–50 loaded tools; the [Advanced tool use post](https://www.anthropic.com/engineering/advanced-tool-use) reports Opus 4 MCP-eval accuracy 49%→74% with tool search, and notes deferred tools don't break prompt caching because they never enter the initial prompt. Same post: programmatic tool calling cut average usage 43,588→27,297 tokens (−37%) on complex research tasks.
- Claude Code ([MCP](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search)): tool search is **on by default** — only tool names + server instructions load at session start; `ENABLE_TOOL_SEARCH=auto[:N]` loads schemas upfront only while they fit under N% (default 10%) of the window; disabled automatically behind non-first-party `ANTHROPIC_BASE_URL` (matches the Headroom caveat in `wiki/open-source-local-context-reducers.md`). Tool descriptions and server instructions are truncated at 2 KB each. MCP tool output warns at 10k tokens and is capped at 25k by default (`MAX_MCP_OUTPUT_TOKENS`).

### 6. Model and effort routing as a cost lever

- Current per-MTok pricing (input / 5m write / 1h write / read / output) from the [pricing page](https://platform.claude.com/docs/en/about-claude/pricing): Fable 5 $10 / $12.50 / $20 / $1 / $50 · Opus 5 (and 4.6–4.8) $5 / $6.25 / $10 / $0.50 / $25 · Sonnet 5 $2 / $2.50 / $4 / $0.20 / $10 (introductory price made permanent) · Sonnet 4.6 $3 / … / $15 · Haiku 4.5 $1 / $1.25 / $2 / $0.10 / $5. Output tokens are 5x input — a reason chrome-heavy *generation* costs more than chrome-heavy *reading*.
- [Effort levels](https://platform.claude.com/docs/en/build-with-claude/effort) (`low`–`max`, default `high`; `xhigh` default on Opus 4.7 in Claude Code) trade thinking depth for token spend; Claude Code exposes `/effort`, per-subagent `effort:`, and thinking budget controls ([model config](https://code.claude.com/docs/en/model-config#adjust-effort-level), [costs](https://code.claude.com/docs/en/costs#optimize-extended-thinking-usage)).
- Caches are model-scoped: any model switch is a full cache miss ([Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache)) — so per-subagent Haiku routing wins only when the delegated work is big enough to beat the cold-start write, and mid-session `/model` flips are the anti-pattern.

## Relevance to this repo

Mapping onto plan 024's measured cost centers:

1. **Session-start ~3.4k tokens (CLAUDE.md 5,186 B + 24 skill descriptions 7,665 B + commands)** — after turn 1 this rides the cache at 0.1x, but it is re-paid at full write price by every new session, every subagent, and every cache-expiry gap (5-minute TTL on API billing). The byte budgets in plan 024 remain the right guardrail; the docs add one lever the plan doesn't use: `skillOverrides: "user-invocable-only"` removes operator-only skills from the startup listing **without touching the hash-pinned vendored SKILL.md files** — a settings-side alternative to upstream trims for part of the 7,665 B. The 1,536-char per-skill truncation is a hard ceiling no description should approach.
2. **~7k tokens per artifact-template turn** — the read half (template as a tool result) is cache-discounted on later turns; the write half is output tokens at 5x input price and caching can't touch it. That makes plan 024's deferred "template-stamping generator" the highest-leverage documented-pattern fix (it's the costs page's "offload processing to hooks" pattern applied to output), ahead of any caching tweak.
3. **Hook quiet path** — the docs confirm `UserPromptSubmit`/`SessionStart` stdout is injected context (10k-char cap); plan 024's quiet-path probe guards the exact channel the docs describe.
4. **`CLAUDE.md`/`AGENTS.md` byte-identical copy** — the memory docs' recommended pattern is `@AGENTS.md` import instead of duplication; token cost is identical, but it would replace the `cmp` divergence check with structure. Optional.
5. **Growing `plans/README.md` (50 KB, advisor-read)** and `wiki/index.md` — the just-in-time retrieval principle ([context-engineering post](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): "find the smallest possible set of high-signal tokens") argues for keeping them index-thin and grep-accessed like `log.md`, and for delegating whole-file reads to a subagent (own window, summary back) rather than the main thread.
6. **Not applicable here**: API-side context editing / memory tool / 1M beta are Messages-API features — Claude Code already ships its own equivalents (auto-compaction, auto memory, `[1m]` aliases), so the repo's guardrails need no API-level work. The free `count_tokens` endpoint is worth using once to calibrate plan 024's bytes→tokens ratio.
