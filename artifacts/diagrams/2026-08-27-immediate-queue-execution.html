Run queued feedback immediately

Three ways to collapse the wait between "Queue for agent" and the agent working. All keep plan 015's rule: only an explicit queue action authorizes autonomous work.

Notes–
A · Session watcher — SZero build: tell a session "watch the queue and work every batch that lands" — that standing sentence is the delegation the tracker rules require. The session arms a Monitor on .scratch/artifact-feedback/issues/ and claims each valid ready+queued batch on arrival. Dies with the session; the prompt-time hook stays as backstop.
B · Run-now button — shippedBuilt 2026-08-27: the tray's Approve · run now files the batch, then spawns a detached two-stage claude -p pipeline — configurable executor and reviewer models (haiku/sonnet/opus selects, defaults sonnet/opus) under a single-flight lock, logging to .scratch/artifact-feedback/runs/, with live Execution polling in the tray.
C · Queue daemon — S/MA standalone watcher (shell loop or systemd --user) running claude -p for any queued batch — survives both the site and the interactive session, and also picks up hand-pasted file:// issues. Strongest autonomy: every queued batch runs with no human present, so it needs an explicit on/off switch.
RiskUnattended edits to the repo. The shipped path keeps: only explicit approval actions dispatch (never needs-triage), one run at a time, results recorded in the issue file. C would need a kill switch on top.
OpenB is live. A is one sentence to any session whenever you want it; build C only if batches must run with nothing else open.
