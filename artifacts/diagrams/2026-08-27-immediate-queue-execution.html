Run queued feedback immediately

Three ways to collapse the wait between "Queue for agent" and the agent actually working. All keep plan 015's rule: only an explicit queue action authorizes autonomous work.

A · Session watcher — SWorks today, zero build: tell a session "watch the queue and work every batch that lands" — that standing sentence is the delegation the tracker rules require. The session arms a Monitor on .scratch/artifact-feedback/issues/ and claims each valid ready+queued batch the moment the file appears. Dies with the session; the existing prompt-time hook stays as backstop. Could be formalized later as a tiny /watch-queue skill.
B · Run-now button — MImmediacy stays a per-batch human click, the closest fit to plan 015's trust model. The review tray gains "Queue and run now"; after writing the issue, the API route spawns headless claude -p "claim and execute <issue>" in the repo (single-flight lock, permission mode to decide), streams the run log into the issue's ## Comments, and the refreshed page shows the outcome. Pairs naturally with the review-inbox direction option. Requires the site to be running.
C · Queue daemon — S/MA standalone watcher (shell loop or systemd --user) that runs claude -p for any queued batch — survives both the site and the interactive session, and also picks up hand-pasted file:// issues. Strongest autonomy: every queued batch runs with no human present, so it needs an explicit on/off switch.
RiskUnattended edits to the repo. Whatever ships keeps: only explicit queue actions dispatch (never needs-triage), one run at a time, every run's result recorded in the issue file, and a kill switch for C. Headless permission mode and token cost are the real decisions inside B and C.
OpenRecommended: use A immediately (it is one sentence to a session), build B as the durable UX. Choose C only if batches must run with nothing else open.
