Integrating claude-diagrams into second-brain

Six branches: package it, store every artifact in the repo, surface it on the site, render plans as pages, make pages talk back to Claude/Codex, and a few wilder ideas. Bold-bordered nodes are the recommended spine.

Notes–
PackageMove ~/src/claude-diagrams to plugins/diagram-plans via git subtree; a root .claude-plugin/marketplace.json makes second-brain itself the marketplace, installed once per machine from the repo path.
Config UIAdd a plugins entry to TOOLS in lib/config-files.ts: a toggle per plugin that edits enabledPlugins and the env block in the chezmoi-managed dotfiles/.claude/settings.json, so Save ⟶ apply ⟶ Commit works as today.
StoreSkill writes three files: artifacts/<slug>.html, .mmd source, .json sidecar (title, type, date, sources, related wiki pages). Sidecar is what the site and index read; HTML stays a plain openable file.
SiteA page-tree transformer (same trick as the Config folder) adds an Artifacts folder; /artifacts/[slug] renders the .mmd with Fumadocs tokens instead of iframing the Geist page, so it matches the wiki and dark mode.
Openerdiagram-open checks port 3000; if the site is running it opens localhost:3000/artifacts/slug, otherwise the file. One artifact, both views.
PlansA second skill turns plans/NNN.md into a page: gantt of steps, badges from the status table, STOP conditions as warning nodes. A file watcher re-renders on save, so plans authored by improve appear automatically.
InteractiveSelect a node or any text ⟶ floating "Ask Claude / Ask Codex" ⟶ POST to site/app/api/ask ⟶ spawns claude -p or codex exec with the artifact source, the selection, and the linked wiki pages as context ⟶ reply streams into a note on the page and is written back to the sidecar and logged.
Expand"Expand this node" sends the node id and asks the agent to rewrite the .mmd with a new subgraph; the page live-reloads. Diagrams grow by clicking, not re-prompting.
WildAn MCP server over artifacts/ lets any Claude session cite past plans; a diff view overlays two git versions of a diagram; a QR code in canvas mode opens the page on your phone via LAN.
RiskThe static export (bun run build) cannot host /api/ask; interactivity is a dev-server feature unless the bridge becomes a tiny separate daemon.
RiskSpawning claude -p from an HTTP endpoint is shell access on localhost; bind to 127.0.0.1 and require a per-session token.
OpenSubtree (single repo, simplest for the config toggle) or keep claude-diagrams a separate repo published to GitHub and only vendored? Subtree is recommended.
OpenWhich agent is the default "Ask" target — Claude Code (has the wiki CLAUDE.md) or Codex? Could be a per-artifact dropdown persisted in the sidecar.
